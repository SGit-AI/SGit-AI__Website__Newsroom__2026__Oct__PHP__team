What a client-side site does not have to care about, and what it must

Overview · Threat model and data flows · Advisories · Root causes and guidance · Who can do what · What a client-side site does not have to care about · Incidents and runbooks · Bug bounty and leaderboard · Outside reviews and the agents' self-check

This site has no server of its own: static pages on GitHub Pages, encrypted vaults whose server cannot read them, and everything else in the reader's browser. Whole classes of attack are gone. The ones that are left are concentrated, and some got worse.

Gone, by design

Why
No server of oursNo SQL injection, no remote code execution, no server-side request forgery, no session fixation, no server to patch. This newsroom tracks two PHP flaws that took thousands of servers offline; this site has no PHP and no server to take offline.
No databaseNothing to dump, no injection into queries, no backups to leak.
No accounts on our sideNo passwords to store, reset or stuff. Readers who keep anything keep it in their own vault, with their own key.
Zero-knowledge storageThe vault server holds ciphertext. A breach of the server is a breach of encrypted blobs; the keys never reach it (except the write-key header noted in SA-2026-032).
Static hostingGitHub Pages serves files with TLS and absorbs traffic; there is nothing to exhaust but bandwidth.
Everything versionedEvery page is the output of a deterministic build of a public commit; any change can be traced, reverted and redeployed.

Moved, and bigger for it

Why
Cross-site scripting is now the big oneWith no server, the reader's browser is where the secrets are: vault keys, signing keys, model keys. Script on the origin reaches all of them (SA-2026-012). The CSP (SA-2026-018) and DOM-building renderers are the answer.
The build pipeline is the serverWhoever can change data/ or build.py changes every page. Push rights are root (SA-2026-023).
The agents are the operatorsAnd they read hostile text for a living. Prompt injection is to this site what SQL injection is to a database site (SA-2026-009, 024, 025).
Public lanes are the only write APIAnyone can write; nobody is authenticated; every drain must treat every row as hostile (SA-2026-010, 013, 028).
The supply chainVendored libraries, pinned actions, the packages CI installs.

PHP October 2026 (php.oct.2026.newsroom.sgit.ai) tracks PHP news for one month. This month that is one story, the two critical PHP security flaws, followed as evidence: every claim with a status and its sources, every source captured, dated and hashed into a private vault. Built and run by one editor and a team of software agents; the roles and the method are public, and the site is rebuilt from the vault, never written by hand.
