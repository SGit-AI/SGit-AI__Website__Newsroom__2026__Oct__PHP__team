Root causes, and the guidance they give

Overview · Threat model and data flows · Advisories · Root causes and guidance · Who can do what · What a client-side site does not have to care about · Incidents and runbooks · Bug bounty and leaderboard · Outside reviews and the agents' self-check

Every finding was handled as an incident: what went wrong, why, what was not in place, and what now stands in the way. Read together, 44 advisories come down to 7 patterns. Each pattern is a rule for every agent.

The patterns

PatternAdvisoriesThe rule it gives
Data reached markup with the wrong encoderSA-2026-001, 003, 011, 012, 015Data is written into HTML only through E() for text and attributes, U() for URLs and J() for JSON inside <script>; in the browser, build DOM nodes and set attributes with setAttribute; never assemble HTML in several regex passes. The CSP is the wall behind this, not a replacement for it.
Something from a public lane or a server was trustedSA-2026-010, 013, 022, 028Every row from a lane and every name from a server is hostile: validate it into a clean record before anything else; never use a server-supplied name as a path; never let a sender set a field the drain owns.
Instructions and material shared one channelSA-2026-009, 014, 024, 025, 035What a model or an agent reads from outside is fenced as material; only the editor's prompt instructs; rights come from the prompt, never from a message; whoever reads hostile text holds as few rights as the work needs.
A secret travelled further than it had toSA-2026-006, 007, 026, 031Give a secret to the one step that needs it; never cache a credential store; pass secrets by stdin, not arguments; keep secret-holding apps on an origin of their own.
A control was a setting, not a boundarySA-2026-005, 008, 023, 034Ask of every control: can the agent it constrains turn it off? If so, it stops mistakes, not attacks. Move the ones that matter to GitHub (rulesets, environments) or the server.
A failure was silentSA-2026-017A control that fails must fail loudly: the gate checks that what the build reads is in git, that every page has its CSP, that every advisory has a root cause.
Side effects came before validationSA-2026-020, 021Check everything an input claims, then write. Allow-list the keys of any object merged from outside.

Every fixed advisory, its root cause and its guard

AdvisoryRoot causeWhat was not in placeWhat prevents it now
SA-2026-001
Captured page titles could close the JSON-LD script block and run on the site
Data was serialised for JSON, not for JSON inside HTML. Two contexts, one encoder.A single helper for JSON inside <script>, and a gate check that every JSON script block parses.The gate fails on any JSON script block that does not parse or contains "<" (security_check.py); the Content-Security-Policy (SA-2026-018) blocks the script even if it gets in.
SA-2026-002
Links built from captured data had no scheme check
Escaping was treated as sufficient for URLs; it stops attribute breakout, not dangerous schemes.A URL allow-list at the point where data becomes an href.The gate fails on javascript:, vbscript: and data:text/html in href, src and action; the CSP blocks javascript: URLs.
SA-2026-003
Article links could inject attributes
html.escape(quote=False) was used for text that later landed inside an attribute.Escaping matched to the output context, and link targets restricted to a safe character set.The gate fails on any inline event-handler attribute in generated HTML (security_check.py, since the editor's go on 25 October).
SA-2026-004
The build read and wrote paths taken from data
Paths were built from data without asking where they could point.Path containment at the two file-system sinks.The gate checks the shape of source slugs.
SA-2026-005
The gate missed most secret formats and never read history
The scanner was written for the secrets the first author knew about.A maintained list of secret shapes, the values of the environment's own secrets, and a history scan.Run by the gate, by the release tripwire on the staged diff, and on every security pass.
SA-2026-006
The synthetic readers' workflow gave every secret to every step
Secrets were scoped to the job for convenience.Least privilege per step, and pinned supply chain.The gate fails on any workflow action not pinned to a commit SHA.
SA-2026-007
Vault keys were stored in the GitHub Actions cache
The cache was treated as data, but a vault clone is a credential store.Knowing which files are credentials, and keeping them out of shared caches.Vault clones live outside the repository and are never cached (REQUIREMENTS.md).
SA-2026-008
The deploy job ran repository code with Pages and OIDC rights
Build and deploy shared one job and one permission set.Separation of the job that runs code from the job that deploys.Pinned actions and persist-credentials: false.
SA-2026-009
The synthetic review mixed untrusted page text with its instructions
Page text was concatenated into the prompt as if it were part of it.A boundary between instructions and material, and least privilege for whoever reads it.REQUIREMENTS.md section 5: untrusted text fenced, no tools or credentials in the call, output constrained and escaped.
SA-2026-010
The subscriptions drain stored whatever arrived on a public lane
Validation lived in the client, which an attacker does not have to use.Server-side (drain-side) validation of every field.Every drain treats every row as hostile (REQUIREMENTS.md). What mail it can cause is SA-2026-027.
SA-2026-011
Small unescaped sinks in the site's scripts
innerHTML built from strings, trusted because the data was ours.Escaping by default.The CSP.
SA-2026-012
The Ask pane: a captured title could run script and reach the reader's vault key
HTML was assembled with regexes in several passes, each pass unaware of the context the previous one had created.A renderer that builds DOM nodes, and a CSP.The CSP (SA-2026-018) blocks inline handlers and injected scripts; the review checklist now asks of every new innerHTML which context each piece of data lands in.
SA-2026-013
Feedback from anyone could carry the mark "enrolled", and one bad row stopped the drain
The drain added its own fields to the sender's object instead of to a clean record.A clean record per row: sender fields and drain fields never mixed.Every drain: validate, then enrich.
SA-2026-014
An agent could write a message signed as the editor
Messages carry identity in a field anyone writes, and nothing verifies it.Authentication of the sender.The gate fails on a message whose sender disagrees with its file name, repeats a header, or claims to be the editor (security_check.py, 25 October); signed messages are SA-2026-024.
SA-2026-015
Unquoted and unchecked links on the fact-check and signals pages
Quoting an attribute was left to each author.A check that catches the class, not the instance.The gate fails on inline event-handler attributes in generated HTML (25 October); the CSP.
SA-2026-016
The editor's bootstrap invitation still had two device slots open
Invitations default to three devices and a two-week life, including the editor's own.Single-use invitations for privileged roles.Recommended: editor-role invitations single-use and expiring within a day.
SA-2026-017
Ignore rules silently dropped files that should have been committed (twice)
A broad ignore pattern, with no check that what the build reads is in git.A check that every file the build reads is tracked.The gate fails on any file under data/, admin/build/, admin/content/ or assets/ that .gitignore hides (security_check.py, 25 October).
SA-2026-018
No Content-Security-Policy on a site that holds secrets in the browser
Defence in depth was not part of the design, because the site started as static pages with no secrets.A second wall behind escaping.Crawled all 802 pages with zero violations; injected handlers, javascript: URLs and scripts are refused. frame-ancestors needs a header (SA-2026-039). The gate fails on a page with no CSP, or one that lets inline or eval'd script run (25 October).
SA-2026-019
The public telemetry report published visitors' cities and regions
One report object served the private vault and the public site.A separate public projection with an explicit allow-list.telemetry_publish.py's rule: counts only, no city, region or time finer than the hour.
SA-2026-020
A refused invitation left a row that a later one could inherit
Side effects before validation.Validate everything, then write.Unit-tested: the escalation is refused.
SA-2026-021
The vault app: prototype pollution and javascript: links from vault data
Merging untrusted objects without a key allow-list.Allow-listed merges; URL scheme checks in every renderer.Proposed: a CSP for the vault app.
SA-2026-022
The conductor's drain used server-supplied names as file paths
Trusting the server's response shape.Shared helpers for drains.Proposed: one shared drain library.
SA-2026-041
The security check printed part of every secret it found
The finding was written to help a person locate the secret, and repeated part of it to do so.An independent scanner over our own security code.GitHub code scanning (CodeQL) now runs on every push, and push protection blocks supported secrets before they reach the repository.
SA-2026-042
Reader answers were inserted into pages as raw HTML
Answers were treated as trusted authored HTML because the team wrote them, so the build skipped E() to keep their bold and italics.A rule that every data string reaches HTML through E(), with an allow-list of inline tags restored after escaping where prose needs them.The self-check after every piece of work (it found this one); the gate's inline-handler and CSP checks of 25 October.
SA-2026-043
The round's write token is readable by every piece of code the round runs
One job both runs repository code and holds the credential to publish its result.Separation of building from publishing: the job that runs repository code holds no write credential.The rule already used for Pages deploys (the job that writes runs no repository code) applied to every job that holds a secret.

PHP October 2026 (php.oct.2026.newsroom.sgit.ai) tracks PHP news for one month. This month that is one story, the two critical PHP security flaws, followed as evidence: every claim with a status and its sources, every source captured, dated and hashed into a private vault. Built and run by one editor and a team of software agents; the roles and the method are public, and the site is rebuilt from the vault, never written by hand.
